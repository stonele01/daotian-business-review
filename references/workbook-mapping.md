# Excel 映射与溯源

先 inspect，再阅读工作表名、标题、合计行、日期和公式缓存。inspect 输出全部非空单元格及坐标，不能仅凭文件名猜周期。公式只有表达式没有缓存时，要求用 Excel / WPS 重算保存，或从可用原始字段另行计算，不能将其当成零。

`examples/mapping.json` 对应 `scripts/make_fixture.py` 生成的模拟工作簿，是最小可验证案例。

映射格式：

- base：顶层固定信息，可包含 `$cell` 引用，建议放 meta、checks、targets、history。
- account_blocks：每块给定明确 rows 数组和 record；不自动跨过合计行。
- `$cell: "工作表!B{row}"`：从当前行读取，支持 nullable 和 scale（万元转元为 10000）。其他字符串是字面量。
- joins：用 name 对齐独立表；aliases 显式记录别名。record 的 check_total 用同名两期金额验证，其他字段加入账号。禁止覆盖已有字段，禁止重复 / 未匹配账号；默认 require_all=true。
- record 内的单元格引用会进入 source_refs，提取记录源文件 SHA256，提取前后核验源文件未改变。

## 原周报格式的迁移提示

这是需要重新检查的候选映射，不是永远不变的表头保证：

| 工作表含义 | 原格式候选 |
|---|---|
| 分销和自营销售对比 | A 账号，B/C 总 GMV，J/K 自营，N/O 消耗，S 代理商 |
| 短视频和货架销售对比 | A 账号，B/C 总 GMV；F/G 短视频、J/K 录播、N/O 商品卡、R/S 其他 |
| 月度完成进度 | 账号位置、目标和实绩以实际表头为准，店播 / 切片排录播等口径必须逐项确认 |
| 旧表三 | 只作差异核验对象；新表三由前述底表独立重算 |
| 历史短视频、类目表 | 逐表确认标题日期，归入独立 history 专题 |

新月份账号行数和位置可能改变。不要写死 27 个账号、9 月日期、旧头部账号名称或旧汇总值。工作表里的百分比优先用同口径分子 / 分母重算；无法重算时标明表内值。

复杂表格可以写一次适配器生成同一 JSON 契约，但要保存原始坐标和异常记录。每张表在口径说明中标明“已使用 / 独立历史 / 排除及原因”。
