# 分析覆盖清单

| 问题 | 计算 / 组件 | 解读边界 |
|---|---|---|
| 全盘变大了吗 | KPI、正向增长与负向抵消瀑布 | 同期天数不同要提示 |
| 增量来自谁 | 账号净增额排序、规模 / 增量散点 | 净贡献允许负数或 >100% |
| 依赖头部吗 | 两期 CR1/CR3、剔除当期头部前后比较 | 观察范围切换只影响标明的组件 |
| 分销掩盖自营下降吗 | 总额上涨且自营下降计数、账号诊断 | 不用全盘上涨代替账号健康 |
| 消耗是否同步产出 | 自营 / 消耗汇总比、账号哑铃图、变化散点 | 缺失分母不补值，非利润 / 广告因果 |
| 变化可拆成什么 | Δ消耗 × 平均比值 + Δ比值 × 平均消耗 | 对称算术恒等式，不命名为因果效应 |
| 渠道哪里变了 | 两期条形、头部与其他拆分、账号渠道热图 | 业务归属与成交渠道不是同一维度 |
| 代理商如何比较 | 总自营 / 总消耗 | 用加权汇总，不简单平均 |
| 目标还有多远 | 实绩 / 目标条形、剩余差额、口径表 | 不同口径不相加；月节奏需 MTD 确认 |
| 每个账号怎么查 | 搜索、变化类型、代理商、排序、指标组、CSV | 筛选范围明确，导出金额元 |
| 历史指标如何变化 | 独立日期专题、逐指标条形与明细 | 不冒充当前数据；转化比例缺分母不算 |

## 文字判断顺序

1. 从程序输出选出影响最大的变化，写清金额、方向和观察范围。
2. 给出反例或结构约束，例如增长集中 / 扩散、总量与自营方向不同。
3. 把数据能说明的事实与需要业务核查的原因分开。
4. 行动写“核查对象、需要证据、判断标准”；没有证据不要写确定原因或承诺提升幅度。

覆盖所有可用指标，不是给每个数字编一句话：相关指标用同一组件比较，重复值放明细，异常和缺失说明理由。避免仪表盘、饼图、3D、无意义环形装饰和用百分比图掩盖绝对量。

扩展新业务字段时，应同时更新契约、图表、明细、单位、溯源与测试。不得仅在图上展示新增字段而忽略校验。
