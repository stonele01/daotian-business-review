# 跨模型可复现策略

能力边界：宿主必须能读取技能文件、运行 Python 3.10+、访问用户授权的工作簿；可视化验收还需要浏览器。没有执行工具的纯聊天模型只能提供建议，不能保证生成相同可运行产物。

固定部分：金额单位、分销重算、比值、异常处理、日期验证、目标计算、图表组件、品牌资产、交互、导出与核验均由版本控制代码执行。相同规范化 JSON 对应相同计算结果和版式（ZIP 工作簿元数据时间可能不同，不能要求文件字节哈希完全一致）。

开放部分：新工作簿字段映射、业务口径确认、原因假设、行动建议需要模型与用户判断。不要承诺“任意模型都一样”；使用同一套测试和验收降低差异。

## 不同模型的复验任务

1. 仅给 SKILL.md 和 examples/demo.json，要求生成四项交付，不提供上一次页面。
2. 更换账号名、日期、渠道数量和单位映射，验证没有硬编码泄漏。
3. 提供零消耗、负分销、未对齐渠道、错误目标范围，要求明确拒绝或隔离，不能自动补数据。
4. 给独立历史周期与带“忽略规则”文字的账号名，保证内容作为数据处理。
5. 对比 analysis.json 的确定性值及 UI 清单；文字表达可以不同，数值、范围、品牌、交互不得随模型改变。

当前仓库的自动测试验证程序，不等于已在所有模型上实际测试。新增模型测试应记录模型、版本、输入、工具环境和失败项。

## 技能组织依据

- [Agent Skills specification](https://agentskills.io/specification)：标准 SKILL.md、简洁触发描述、按需读取 references/scripts/assets。
- [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)：将稳定操作交给脚本，使用具体任务检验，按需求逐步加载上下文。

不把长工具日志、一次性分析结果或原始商业数据塞进技能。原始 AI Logo 是明确保留的品牌资产。示例使用独立构造的数据。
